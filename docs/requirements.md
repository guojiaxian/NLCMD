# nlcmd 需求文档

| 项目 | 内容 |
| --- | --- |
| 产品名称 | nlcmd（Natural Language Command，暂定名） |
| 版本 | v1.0（草案，待评审） |
| 日期 | 2026-08-21 |
| 目标平台 | Linux x86_64 / arm64，纯终端环境（SSH 可用） |

## 1. 项目概述

### 1.1 背景

运维和开发人员经常清楚地记得"要做什么"，却记不住"具体命令怎么写"（如 find 的参数组合、awk 的语法等）。查搜索引擎需要切换窗口、筛选过时答案，效率低。

### 1.2 目标

提供一个运行在 Linux 终端中的 CLI 应用：用户用自然语言描述意图，由大模型生成对应的 shell 命令，经用户**确认/修改**后执行并回显结果。定位为"终端里的自然语言命令助手"。

### 1.3 核心价值

- 不记忆命令细节，只需描述意图
- 命令必须经过用户过目、可编辑后才执行，安全可控
- 多候选命令 + 多选执行，覆盖不同实现思路
- 预置国内主流大模型模板，5 分钟完成部署

## 2. 用户与典型场景

**目标用户**：Linux 服务器运维人员、后端开发人员、需要频繁操作终端的技术人员。

| 编号 | 场景 | 用户输入示例 | 期望输出示例 |
| --- | --- | --- | --- |
| S1 | 查找文件 | 查询根目录下名字中包含vscode的文件 | `find / -iname "*vscode*" 2>/dev/null` |
| S2 | 进程排查 | 查看当前占用内存最高的5个进程 | `ps aux --sort=-%mem \| head -6` |
| S3 | 日志分析 | 统计access.log中出现次数最多的10个IP | `awk '{print $1}' access.log \| sort \| uniq -c \| sort -rn \| head -10` |
| S4 | 网络排查 | 查看80端口的占用情况 | `ss -tlnp \| grep :80` |
| S5 | 系统管理 | 把/var/log目录打包并按日期命名 | `tar czf /var/log-$(date +%F).tar.gz /var/log` |

## 3. 功能需求

优先级说明：P0 = v1.0 必须实现；P1 = v1.0 尽量实现；P2 = 后续版本。

### FR-01 应用启动与交互循环（P0）

- 启动后显示欢迎信息：版本号、当前使用的模型、帮助提示
- 显示提示符 `nl> ` 等待用户输入
- 支持输入历史（上/下键翻阅）
- `/exit` 或 Ctrl+D 退出；Ctrl+C 清空当前输入
- 验收：启动到可输入 < 1s；正常退出码为 0

### FR-02 自然语言命令生成（P0）

- 用户输入中/英文自然语言描述
- 调用用户配置的大模型，生成 1~3 条候选 bash 命令，每条含：命令本体、一句话中文描述、风险等级
- 生成期间显示加载动画（spinner）与提示文案
- 与"在 Linux 上执行操作"无关的输入（如打招呼、闲聊），返回友好提示而非强行生成命令
- 验收：输入 S1 示例，返回可执行的 find 命令

### FR-03 候选命令展示（P0）

- 以编号列表展示候选命令：命令全文 + 描述 + 风险标记（绿/黄/红）
- 命令过长时合理换行，不破坏复制

### FR-04 命令选择：单选 / 多选 / 全部（P0）

- 直接回车：默认选择第 1 条
- 输入序号：选择指定一条（如 `2`）
- 逗号分隔序号：多选（如 `1,3`），按顺序执行
- 输入 `a`：选择全部
- 输入 `q` 或 Esc：取消，回到输入状态

### FR-05 命令编辑（P0）

- 选中的命令（多条时逐条或合并展示）进入**可编辑输入行**，内容预填充
- 支持完整行编辑：左右方向键、Home/End、退格、删除、粘贴
- 回车执行；Esc 取消并返回候选选择界面

### FR-06 命令执行与结果展示（P0）

- 通过 bash 执行命令，输出实时流式回显（不等待命令结束才打印）
- 执行完毕显示退出码与耗时；成功/失败有视觉区分
- 多条命令顺序执行时：前一条失败（非 0 退出码）时询问是否继续

### FR-07 执行中断与超时（P1）

- 执行中 Ctrl+C 可终止当前命令，回到输入状态
- 命令执行超时可配置（默认 600s，0 表示不限时），超时自动终止

### FR-08 大模型配置：预设模板 + 自定义（P0）

- 预置服务商模板，开箱即用（详见设计文档 §6）：DeepSeek、GLM（智谱）、通义千问 Qwen、Kimi（月之暗面）（已与用户确认为国内四家）
- 每个模板只需填 API Key 即可使用；另保留"自定义"模板，可接任意 OpenAI 兼容接口（api_base / api_key / model）
- 可配置项：api_base、api_key、model、请求超时、temperature
- API Key 支持从环境变量读取（如 `NLCMD_API_KEY`、`DEEPSEEK_API_KEY`），优先级高于配置文件

### FR-09 首次运行配置向导（P0）

- 检测到无配置文件时自动进入向导：选择服务商 → 输入 API Key → 可选连接测试
- 测试成功后写入配置并进入主界面；失败给出明确原因（网络/Key 无效等）

### FR-10 运行时切换模型（P1）

- `/model <名称>`、`/provider <名称>` 切换当前使用的服务与模型，无需重启
- `/model` 不带参数时列出可用模型

### FR-11 内置命令（P0/P1）

| 命令 | 优先级 | 作用 |
| --- | --- | --- |
| `/help` | P0 | 显示帮助 |
| `/exit`、`/quit` | P0 | 退出 |
| `/config` | P1 | 重新运行配置向导 |
| `/model`、`/provider` | P1 | 查看/切换模型 |
| `/history` | P1 | 查看最近执行过的命令 |
| `/retry` | P2 | 用上一次输入重新生成 |

### FR-12 危险命令防护（P0）

- 对生成/编辑后的命令做本地风险评估：safe / medium / dangerous
- dangerous（如 `rm -rf /`、`mkfs`、fork 炸弹等）：红色警示面板，需手动输入 `yes` 才执行
- medium：黄色提示，正常回车确认即可
- 风险评估独立于大模型输出（本地规则二次校验），防止模型漏判

### FR-13 历史记录（P1）

- 输入历史：上下键翻阅（会话内）
- 执行历史：记录最近 N 条已执行命令（含时间、退出码），`/history` 查看

### FR-14 部署与卸载（P0）

- 提供一键安装脚本（curl | bash）
- 支持 pipx 安装；支持源码安装
- 仅依赖 Python 3.7+，无系统级编译依赖
- 提供卸载方式；`nlcmd --version` 可验证安装

## 4. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 冷启动 < 1s；LLM 请求超时默认 30s（可配置）；命令输出流式回显 |
| 安全 | API Key 文件权限 0600；日志不打印 Key；危险命令必须人工确认；绝不自动执行未经确认的命令 |
| 兼容性 | Linux 主流发行版（Ubuntu/Debian/CentOS/Rocky/openEuler 等）；x86_64/arm64；纯 SSH 终端可用，无需 GUI |
| 可维护性 | 模块化分层；核心逻辑（解析/安全/配置）有单元测试 |
| 易用性 | 首次运行向导引导；中文界面；`/help` 随时可查 |

## 5. 边界与非目标（v1 明确不做）

- 不是聊天机器人：不闲聊、不回答与执行 Linux 操作无关的问题
- 不后台自动执行任何命令（必须人工过目确认）
- 不支持 Windows / macOS（架构上不排除，v1 不承诺）
- 不做编辑器级的命令补全 / 语法高亮（v2 考虑）
- 不做多 API Key 轮询、代理池
- 不内置大模型，必须依赖外部 API（可经自定义模板接入本地 vLLM 等兼容服务）

## 6. 端到端验收场景

1. **全新安装**：一键脚本安装 → 首次启动 → 配置向导（选 DeepSeek，填 Key，测试连通）→ 输入 S1 → 得到候选 → 编辑 → 执行 → 看到结果
2. **多选执行**：输入 S2 → 输入 `a` → 逐条确认执行，输出正确
3. **危险拦截**：诱导生成危险命令时，出现红色警示，输入 `no` 拒绝执行
4. **错误恢复**：填错 API Key → 得到明确错误提示 → `/config` 修正后恢复正常
5. **切换模型**：`/model glm` 切换后继续正常使用
6. **中断**：长时间命令（如 `find /`）执行中 Ctrl+C 可中断并返回提示符
